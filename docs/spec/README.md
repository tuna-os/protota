# Vendored GNOME GUI specification corpus

This directory is a **verbatim, read-only snapshot** of selected files from
[hanthor/gnome-gui-spec](https://github.com/hanthor/gnome-gui-spec). Nothing
here is generated by Protota, and no Protota code, script, or test reads it —
it is a reading reference for humans and agents working on preset conformance.

Protota's own component documentation is generated from the widget registry by
`scripts/generate-component-reference.mjs` into [`docs/components.md`](../components.md);
that file, not this directory, is the source of truth for what Protota renders.

## What was vendored, and what was not

Vendored: `audits/`, `reference/` (including the mirrored HIG pages and the
645-icon catalogue), `tokens/`, `COMPONENT-LIBRARY.md`, `INTENT-MAP.md`.

Deliberately **not** vendored:

- `components/` (36 per-widget files) — Protota's widget contract comes from its
  own registry, and a second hand-written list would drift from it.
- `skills/`, `SKILL.md`, `ONBOARD.md`, `INDEX.md`, `QUICKSTART.md`,
  `GNOME-AGENT-GUIDE.md` — agent-harness routing for *building* GNOME apps,
  which is not what Protota does.
- `scripts/` (`lint-app.sh`, `check-icons.sh`) — HIG linting of app source
  checkouts; Protota has no app checkout to lint.

Add a file here only when a specific Protota consumer needs it, and record the
reason. The exclusions above are the point, not an oversight.

## Refreshing

The snapshot is pinned, so it rots silently. To refresh, re-copy the same path
set from a newer upstream commit and update the table above:

```sh
git clone --depth 1 https://github.com/hanthor/gnome-gui-spec /tmp/gnome-gui-spec
rsync -a --delete \
  --include='audits/***' --include='reference/***' --include='tokens/***' \
  --include='COMPONENT-LIBRARY.md' --include='INTENT-MAP.md' \
  --exclude='*' /tmp/gnome-gui-spec/ docs/spec/
```

(`docs/spec/README.md` is Protota-authored; keep it when refreshing.)
